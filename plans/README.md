## Dependency notes

- No hard dependencies between plans 001-005. But 001, 002, 003, and 005 all edit
  `src/app/movimentacoes/actions.ts` in **different regions** (001: top of two
  functions; 002: the upload block; 003: the JSON parse block; 005: the
  top-of-file constants). To avoid merge friction when done sequentially, land
  in the order **001 → 002 → 003 → 005**. 004 touches different files and can
  go anytime.
- If a Vitest setup lands later, each plan's "Test plan" section says which
  tests to add retroactively.
- **006 → 007**: 007 (UI) can execute standalone using a stub lookup function
  (`src/lib/kit-funcao-stub.ts`) — it does not need 006's schema to compile or
  run. But the feature isn't truthful/demoable until 006 lands and the stub's
  body is swapped for a real query against `epi.kit_funcao`. Land 006 first if
  possible to avoid shipping a UI that always shows "sem-kit".

## Findings considered and rejected

So nobody re-audits these:

- **PDF route "unauthenticated IDOR"**: rejected. The Next proxy (`src/proxy.ts`)
  matcher covers route handlers — an anonymous request to
  `/colaboradores/[id]/pdf` redirects to `/login` (verified: 307). Read access
  across perfis among *authenticated* users is by design (almoxarife is central
  and sees all colaboradores per `CONTEXT.md`), not a vulnerability.
- **Storage RLS "any authenticated user can upload/delete"**: rejected. This is
  a deliberate project decision (the original signature-bucket RLS task chose
  authenticated-only, not per-perfil). Server actions add the perfil gate
  (plan 001). Not a bug.
- **Signature upload + insert "not transactional"**: rejected as stale. The
  current signed-delivery flow uploads the signature *before* the DB insert and
  returns an error if the upload throws (`movimentacoes/actions.ts:73-86`), so a
  row is never written without its signature URL. The finding described an
  earlier single-item version that no longer exists.
- **Quantity-sign `Math.abs` "could be flipped"**: rejected. The `itens.filter(
  (i) => i.quantidade > 0)` upstream guarantees positive input before the sign
  is applied; the code is safe. Cosmetic at most.
- **postcss CVE / `ilike` SQL injection on CA search**: rejected. postcss issue
  is dev-only noise-floor with no user-controlled CSS here; PostgREST
  parameterizes `ilike` arguments — no injection.
- **Kit-per-função not modeled**: rejected as a *finding* — it is a consciously
  deferred backlog item documented in `CONTEXT.md` "Fora de escopo", not an
  oversight. It remains a legitimate future feature (see Direction below).

## Direction findings (maintainer's call — not bugs)

Grounded feature options surfaced by the audit, deferred to product judgment:

- **Devolução invisible on the ficha/PDF.** `colaboradores/[id]/pdf/route.ts:36`
  and the ficha page filter to `["Entrega","Substituicao"]`, so returns are
  recorded but never appear on the signed legal document. If returns are a real
  NR-06 lifecycle event, the ficha should show them. Effort: M.
- **`limite_por_entrega` configured but never enforced.** The column is editable
  in the catalog UI but no delivery-form or server-action check uses it — a
  supervisor-set limit is silently ignored. Effort: M. Decide warning vs. hard
  block before building.
